# Lighthouse OpenClaw 与 Hermes 镜像功能后续规划

> 本文档用于记录 Lighthouse 围绕 OpenClaw 与 Hermes 应用镜像、应用管理面板、Agent 资产与控制面能力的后续规划。当前内容基于已有规划整理，后续可随着交互方案、接口方案和研发排期继续补充。

## 1. 背景

OpenClaw 与 Hermes 都是 Lighthouse 面向 Agent 应用镜像方向的重要能力入口。当前两类镜像在产品定位、应用面板成熟度、控制面能力、资产沉淀方式上仍处于逐步收敛阶段，需要通过统一前端体验、补齐 Hermes 面板能力、沉淀更新日志和资产迁移机制，逐步形成可持续迭代的 Agent 应用镜像体系。

本阶段规划的核心目标不是一次性重做全部能力，而是先把用户可感知的应用管理入口统一起来，再逐步完善面板功能、Agent 资产流转和控制面形态。

## 2. 目标

- 统一 OpenClaw 与 Hermes 应用管理面板的前端交互和信息架构，降低多镜像维护成本。
- 建立面向用户和内部协作的更新日志机制，让镜像版本、面板更新和能力变化可追踪。
- 支持 Agent 资产迁移，为用户从已有 Agent 应用迁移到 Lighthouse 镜像体系提供基础能力。
- 推进控制面整体向 `agent-cli` 改造，增强自动化、可维护性和 Agent 原生操作体验。
- 补齐 Hermes 应用面板能力，使其逐步达到可对标 OpenClaw 的产品完整度。
- 保持 OpenClaw 应用面板的日常迭代，持续优化已经上线能力。

## 3. 规划范围

### 3.1 纳入范围

- OpenClaw 与 Hermes 应用管理面板前端统一。
- OpenClaw 与 Hermes 应用镜像相关的更新日志能力。
- Agent 资产迁移能力的产品与技术方案沉淀。
- 控制面 `agent-cli` 化改造。
- Hermes 应用面板能力补齐。
- OpenClaw 应用面板持续迭代。

### 3.2 暂不纳入范围

- 非 Agent 应用镜像的控制台重构。
- 与 OpenClaw、Hermes 无关的 Lighthouse 通用资源管理能力。
- 新增未明确进入规划的 Agent 应用镜像品类。

## 5. 后续规划

### 5.1 OpenClaw 与 Hermes 应用管理面板前端“大一统”

**当前状态：** 前端交互方案已输出 1.0 版本，后续待相关方一起评审，通过后进入开发。

**规划方向：**

- 以 1.0 交互方案为基础，抽象 OpenClaw 与 Hermes 共用的应用管理面板框架。
- 将模型配置、通道接入、技能/插件管理、版本信息、文档入口等通用模块统一到同一套前端信息架构中。
- 保留不同镜像的差异化配置项，避免为了统一而削弱 OpenClaw 或 Hermes 的核心能力表达。
- 建立面板模块的配置化能力，让后续新增 Agent 镜像可以复用统一框架。

**预期产出：**

- 应用管理面板统一交互说明。
- OpenClaw/Hermes 面板模块差异表。
- 前端组件与页面结构拆分方案。
- 1.0 方案评审结论与开发排期。

### 5.2 更新日志

**当前状态：** 前后端方案已对齐完毕，预计下周优先排期上线。

**规划方向：**

- 为 OpenClaw 与 Hermes 镜像建立统一更新日志入口，用于记录镜像版本、社区项目版本、腾讯云面板版本和重要能力变更。
- 更新日志需要同时服务用户侧展示和内部版本追踪，避免用户只能通过零散文档理解当前镜像能力。
- 前端展示建议采用按时间分组的更新流，后端可返回结构化内容块，便于控制台按统一样式渲染。
- 如后续需要未读提醒，可将阅读状态与更新日志内容解耦，单独维护用户维度的已读关系。

**预期产出：**

- 更新日志展示入口与交互方案。
- 已对齐的更新日志数据结构与接口方案。
- OpenClaw/Hermes 首批更新日志内容模板。
- 镜像版本、官方项目版本、面板版本之间的展示规则。

### 5.3 Agent 资产迁移

**当前状态：** 整体方案框架已经确定，具体迁移细节和研发排期待进一步确认。

**规划方向：**

- 梳理 OpenClaw 与 Hermes 涉及的 Agent 资产类型，包括模型配置、通道配置、技能/插件、记忆、工作流、用户自定义配置等。
- 明确哪些资产支持迁移，哪些资产仅支持重新配置，哪些资产需要用户授权后迁移。
- 设计迁移前检查、迁移执行、迁移结果回执和失败恢复机制。
- 在应用管理面板中提供迁移状态可视化，降低用户对迁移过程的不确定感。

**预期产出：**

- Agent 资产类型清单。
- 资产迁移兼容性矩阵。
- 迁移流程与异常处理方案。
- 具体功能边界和排期确认。
- 面向用户的迁移说明与风险提示。

### 5.4 控制面整体改造成 `agent-cli`

**当前状态：** 控制面向 `agent-cli` 改造的方向已明确，具体细节和排期待进一步确认。

**规划方向：**

- 将当前面板侧的关键控制能力逐步沉淀为 `agent-cli` 可调用的操作。
- 用 CLI 承接安装、配置、检查、升级、诊断、迁移等高频控制面动作。
- 面板前端更多承担可视化、状态呈现和用户确认，具体执行逻辑尽量下沉到统一 CLI。
- 为后续 Agent 自动化运维、批量操作和问题诊断提供统一入口。

**预期产出：**

- `agent-cli` 能力边界说明。
- 面板动作到 CLI 命令的映射表。
- CLI 执行状态、错误码和日志规范。
- 面板与 CLI 的调用链路方案。
- 具体开发排期和阶段拆分。

### 5.5 Hermes 应用面板功能逐步补齐

**当前状态：** 作为日常跟进事项持续推进，不做特殊排期。

**规划方向：**

- 以 OpenClaw 应用面板作为能力参照，梳理 Hermes 当前缺失的核心功能。
- 优先补齐影响用户完成初始化和日常使用的能力，例如模型配置、通道接入、技能管理、版本说明、文档入口和健康检查。
- 对 Hermes 特有能力单独设计呈现方式，避免完全照搬 OpenClaw。
- 每次补齐都同步更新日志，形成用户可感知的版本节奏。

**预期产出：**

- Hermes 面板能力缺口清单。
- Hermes 面板日常补齐优先级。
- Hermes 特有能力展示方案。
- 日常迭代记录。

### 5.6 OpenClaw 应用面板日常迭代

**当前状态：** 作为日常迭代事项持续推进，不做特殊排期。

**规划方向：**

- 保持 OpenClaw 面板现有能力的持续优化，包括配置流程、状态反馈、错误提示、文档链接和版本信息展示。
- 将 OpenClaw 日常迭代中沉淀出的通用模块反哺到 OpenClaw/Hermes 统一面板框架。
- 对高频用户问题建立面板内自解释能力，减少用户跳转文档或人工咨询的成本。
- 持续验证 OpenClaw 面板作为后续 Agent 镜像管理体验样板的可复用性。

**预期产出：**

- OpenClaw 日常迭代 backlog。
- 可复用面板模块清单。
- 用户反馈与面板优化记录。
- 与统一面板框架的同步机制。

## 6. 阶段拆分建议

### 第一阶段：统一入口与文档化

- 组织 OpenClaw/Hermes 应用管理面板 1.0 交互方案评审，并在评审通过后进入开发。
- 输出统一面板模块差异表。
- 推进已对齐的更新日志方案进入开发排期，预计下周优先上线。
- 梳理 Hermes 面板能力缺口，纳入日常跟进。

### 第二阶段：能力补齐与版本追踪

- 按日常节奏推进 Hermes 应用面板核心能力补齐。
- 在 OpenClaw 与 Hermes 面板中接入更新日志入口。
- 将版本信息、面板更新信息、官方项目更新信息统一展示。
- 开始沉淀 OpenClaw 可复用模块。

### 第三阶段：资产迁移与 `agent-cli` 化

- 在已确定的 Agent 资产迁移整体框架上，继续确认具体迁移细节和排期。
- 完成 Agent 资产类型清单和迁移兼容性矩阵。
- 在排期明确后设计并实现首批资产迁移能力。
- 梳理面板控制动作与 `agent-cli` 命令映射。
- 待 `agent-cli` 细节和排期确认后，将高频控制面动作逐步迁移到 `agent-cli`。

### 第四阶段：规模化复用

- 将统一面板框架推广到更多 Agent 应用镜像。
- 基于 `agent-cli` 提供更稳定的诊断、升级和迁移能力。
- 建立更新日志、资产迁移、面板补齐和日常迭代的长期协作机制。

## 7. 关键依赖

- OpenClaw/Hermes 应用管理面板 1.0 交互方案评审结论。
- OpenClaw 与 Hermes 当前镜像能力、版本机制和配置方式。
- 已对齐的更新日志接口与内容模型设计。
- Agent 资产定义和迁移边界。
- `agent-cli` 的技术方案、执行环境和面板调用方式。

## 8. 待确认问题

- 应用管理面板“大一统”1.0 方案评审后，是否需要调整开发范围或优先级。
- Agent 资产迁移的首批支持范围是 OpenClaw 到 Hermes、Hermes 到 OpenClaw，还是从外部环境迁入 Lighthouse。
- `agent-cli` 是仅用于实例内执行，还是同时承担控制台后端的标准执行层。
- Hermes 面板补齐和 OpenClaw 面板迭代在日常跟进中是否需要固定记录口径。
- OpenClaw 日常迭代是否需要单独维护版本节奏，还是统一纳入 Agent 镜像面板版本节奏。

## 9. 建议下一步

1. 组织 OpenClaw/Hermes 应用管理面板 1.0 方案评审，评审通过后进入开发。
2. 推动更新日志功能按下周优先排期上线，确保前后端已对齐方案进入实现阶段。
3. 在已确定的 Agent 资产迁移框架上，继续确认首批迁移范围、具体细节和排期。
4. 梳理控制面动作清单，继续确认 `agent-cli` 改造细节和排期。
5. 将 Hermes 面板补齐与 OpenClaw 面板迭代纳入日常跟进，持续记录能力变化和用户反馈。
